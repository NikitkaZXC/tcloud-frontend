# CLAUDE.md

This file provides guidance to Claude Code when working with code in this repository.

## Project

Web UI for `../tcloud-backend` (FastAPI, Telegram-backed file storage). Vite + React 19 + TS, Tailwind v4 + shadcn/ui (`src/components/ui`, add with `npx shadcn@latest add <name>`), TanStack Query, react-router. UI text is Russian and English (`lib/i18n.ts`). Overview in `README.md`; how it works, with Mermaid diagrams, in `docs/` (`architecture.md`, `data-flow.md`, `uploads-and-tasks.md`, `ui.md`, `theming.md`).

## Commands

```bash
npm run dev     # :5173, proxies /api to API_URL or http://127.0.0.1:8000
npm test        # vitest (src/**/*.test.ts, component tests *.test.tsx with jsdom + Testing Library)
npm run test:cov  # with v8 coverage (coverage/)
npm run build   # tsc -b && vite build
npm run lint    # oxlint
docker build -t tcloud-frontend .   # nginx, API_UPSTREAM env
```

CI: `.github/workflows/ci.yml` (push to `main` + PR, concurrency cancels older runs: `npm ci`, lint, test, build on Node 26, same as `Dockerfile`; bump both together). Dependabot: `.github/dependabot.yml` (monthly npm, docker, github-actions; each ecosystem in one grouped PR, `open-pull-requests-limit: 2`).

## Architecture

- `src/lib/api.ts`: every call goes through `request`/`api.*` (prefix `/api`, `credentials: same-origin`, one refresh on 401, errors as `ApiError` with backend `code`; 429 → one shared toast `notifyRateLimit` (id `rate-limited`, not on `/auth/*`; quota codes `send_quota_exceeded`/`too_many_upload_sessions` are plain errors, `QUOTA_CODES`), queries retry only after `retry_after` via `queryRetry`/`queryRetryDelay` in `main.tsx`; error toasts go through `showError`, which skips 429). `src/lib/types.ts` mirrors backend response schemas (`src/application/schemas` there) — update it when the API changes.
- Mutations use `hooks/use-action.ts` (toast on error, invalidate query keys). Query keys: `me`, `storages` (`staleTime` 5 s), `folder/<path>/<sort params + limit>` (`listingKey`, infinite), `task/<id>` (fetched in batches by `taskLoader`: one `GET /api/tasks?ids=` per tick, omitted ids = 404), `task-counts`, `users`, `user/<id>`, `grants/<id>`, `api-keys/<id>`, `upload-sessions/<id>` (user page, managers cancel a user's resumable uploads), `sessions`, `telegram`, `telegram-devices`, `health`, `account` (`useAccount`, `staleTime` 60 s; tasks and storage create/delete invalidate it via `storageChangeKeys`, so the channels ring counts own changes at once), `activity/<path>`, `search/<api query>`, `mimes/<path>`.
- Tasks are tracked by id in localStorage (`lib/tasks.ts`); the backend has no "my tasks" list on purpose. `tcloud.tasks.pending` holds ids not yet reported: `TaskWatcher` reports a finished pending task once (`reportTask`), forgets done non-archive ones, invalidates right away, once per batch response (`taskFolders`); running tasks poll 1 s, queued 5 s (`pollInterval`); upload responses are put in the cache (`setQueryData`) before `trackTask`, cancel also refetches the task; list capped at `MAX_TASKS`.
- User preferences live on the server (`GET/PATCH/DELETE /api/account/settings`, also `settings` in `/users/me`): `lib/settings.ts` store (`useSettings`, `updateSettings` optimistic + revert, requests serialized because the backend merge is not atomic, `hydrateSettings` from `useMe`), page `/settings`. Never add new localStorage prefs; `tcloud.mirror` (theme/language before `/users/me`) is a mirror only. Old `tcloud.view`/`sort`/`theme`/`feature.*` are migrated once (`migrateLegacy`) and removed.
- Other localStorage keys (`tcloud.onboarding.dismissed`, `tcloud.sidebar`, `tcloud.dashboard.layout` / `tcloud.dashboard.hidden` / `tcloud.file_columns` / `tcloud.page_size` = fallback copies of `interface.dashboard_layout` / `interface.dashboard_hidden` / `interface.file_columns` / `interface.page_size`, read only while the server omits them) go through `lib/prefs.ts` or try/catch; they are conveniences only.
- Route pages except `/login` and `/files` are `React.lazy` (`App.tsx`, `Suspense` around `<Outlet />` in `Layout`); `vite.config.ts` splits `react` and `vendor` chunks (`build.rolldownOptions.output.codeSplitting`), `qrcode.react` stays in the telegram chunk (`docs/architecture.md`).
- Layout is a left sidebar (`components/layout.tsx`, drawer on mobile). The command palette (`components/command-palette.tsx`) drives `FolderView` through the `tcloud:folder-action` window event (`lib/commands.ts`).
- i18n (own, no deps): every user-visible string goes through `t(key, params)` from `lib/i18n.ts`; keys live in `lib/locales/ru.ts` (source of the `Key` type) and `en.ts` (`Record<Key, Entry>`, same keys enforced by tsc and `i18n.test.ts`). Plurals are `{one, few, many, other}` objects picked by `Intl.PluralRules` with `{n}`. Language = `interface.language` or the browser (`resolveLang`); `App` remounts on change (`key={useLang()}`), so module-level constants must hold keys, not text. Dates/sizes/collation use `getLang()`. Ctrl+K commands carry `keywords` in both languages (`tAll`). Backend codes map to `error.<code>` keys in `errorMessage`/`errorText`; `validation_error` shows the first `details` field + `msg` (`error.invalidField`), `http_error` the backend `message` (bodies parsed by `errorBody`).
- Sign-in and Telegram errors are mapped from backend `code` in `lib/auth.ts` (`describeError`, `retryAfterOf`); the Telegram wizard step logic is there too.

## Gotchas

- Proxies must keep the `Host` header (Vite default, nginx `$http_host`): the backend Origin check compares `Origin` with `Host`.
- Do not duplicate backend access rules; show actions and surface `403`.
- Telegram QR must be rendered locally, never via external QR services. It carries `favicon.svg` in the center (`QR_LOGO`, 48/216 px, `excavate`, `level="H"`), always black on white in every theme.
- Theme: lo-fi pixel EX8 style on the green palette (#051F20…#DAF1DE); dark in `:root`, light in `:root.light`, presets `sunset`/`navy`/`lavender`/`clay` in `:root[data-theme=…]` (light presets also get `.light`; every token incl. `--backdrop` per preset, AA contrast) (`lib/theme.ts` over `interface.theme` = `dark`|`light`|`system`|preset id; `system` picks only dark/light; `system` follows `prefers-color-scheme` live via `resolveTheme`, the sidebar toggle shows the resolved theme and sets the opposite explicitly; toggle in the sidebar profile and on `/settings`; Tailwind `dark:` = no `.light`). Font: Departure Mono only, for every piece of text (self-hosted `public/fonts/DepartureMono-Regular.woff2?v=1`, `@font-face` + preload with the same URL, nginx caches `/fonts/` immutable for a year so bump `v` in both when the font changes, no Google Fonts); generic `monospace` is the only fallback; never add another font or `font-family`. Regular only: `font-synthesis: none`, no `font-medium/semibold/bold`, emphasis by size, uppercase + tracking or colour tokens. Sizes on its 11 px/em grid: 11 (`text-xs`, labels, meta, uppercase buttons), 16.5 (`text-sm`/`text-base`, body), 22 (`text-lg`, `fx-pixel` small display, ring centers), 33/44 (stats, page titles), 66/88 hero only; no other sizes. Sonner sets its own font/size unlayered, overridden in `index.css`. Rejected: Tiny5, IBM Plex Mono, Handjet, Pixelify Sans (no Cyrillic О/П), JetBrains Mono, Manrope, any font mixing. Logo (24×24 pixel art, cloud with a paper plane over a storage unit with read/write LEDs): `Logo` in `components/fx.tsx` = `public/logo-dark.svg` on dark themes, `logo-light.svg` on light ones (`dark:` toggle), only at 24/48 px; favicons in `public/` (`favicon.svg` with background, `favicon-48/96.png`, `apple-touch-icon.png`), linked with `?v=2` in `index.html` (bump when the icon changes), no web manifest. Effects live in `src/index.css` (`fx-*` classes, shadcn tweaks via `data-slot`) and `components/fx.tsx` (`PageTitle`, `Section`, `Stat`, `Ring`, `ChannelsRing`, `Logo`, `StorageIcon`, `StatusChip`/`StatusLight`, `WireCubes`); animations are smooth (ease curves, only `transform`/`opacity`; `steps(1)` only for read/write/busy LED blinks), counters/rings tween from the last value (`useTween`), upload progress is throttled (`SENDING_TICK_MS`); every animation must stay off under `prefers-reduced-motion` and when `interface.animations` is off (`:root.still`, `prefersReducedMotion()`). Color only for signals; no glitch/scanline/CRT effects.
- Storages page shows per-storage size and file count (`total_size`, `files`) but no capacity/fill bars: Telegram channels have no size limit. Channel limit ring: `channelUsage` (`channels_used`/`channels_limit` from `GET /api/account`, fallback 500/1000 with an honest label). `/account` is always 200; `telegram_connected: false` (other fields `null`) shows "Telegram not connected" and hides Premium/file-limit rings.
- Storage read/write lamps: `useStorageIo()` (one global state; non-cancelled sending + tracked upload tasks = write; archive tasks `archiving` = read) merged (`mergeIo`) with `GET /api/storages/activity` (anyone, while an operation runs + 1 s tail; polled `IO_FAST_POLL_MS` 500 ms while any lamp is lit, else `IO_IDLE_POLL_MS` 3 s, not in background tabs). Downloads/previews have no end event, so `markRead` (`lib/reads.ts`) only pokes a server refetch (`onRead`, 300 ms) and keeps the name 5 s for `IoBanner`. Local lamps go off the moment the operation ends; after that the server's `true` of that kind is ignored until a sample newer than end + `ACTIVITY_TAIL_MS` (`endIo`/`freshServerIo`). `lingerIo` keeps short ones lit ≥ `IO_MIN_MS` from their start, never as a tail.
- `task.progress` from the API is a percent (0–100): always go through `taskFraction`; `step_progress` is 0..1 (`stepFraction`). Step labels/trail/cancel rules live in `lib/steps.ts` (`stepLabel`, `taskPhases`/`trail`, `isMeasured`, `canCancel`; `hintTask` = in-memory source/encrypt per task id); speed/eta only for measured steps. Body uploads are cancelled via `cancelSending` (AbortController), tasks via `POST /tasks/{id}/cancel`. Files > `CHUNK_SIZE` (64 MiB) go through upload sessions (`uploadChunked`/`resumeUpload` in `lib/upload.ts`, chunks by the server's `chunk_size`, retries via `chunkRetryDelay`, cancel = abort + `DELETE`); unfinished sessions live in `localStorage` `tcloud.uploads.sessions` (state, not a pref, every access in try/catch) and show paused in `FolderUploads` until the file is re-picked (`sameFile`). `file_limit` in `/account` is the Telegram part size, not an upload cap; the cap is root-only `uploads.max_file_size` (`413 too_large` with `limit`, formatted by `errorParams` in `lib/api.ts`). `409 conflict` from a dialog upload (single or session create) is asked in `ConflictDialog` (mounted in `Layout`, store `askConflict`/`answerConflict`/`useConflicts` in `lib/upload.ts`, one question at a time, «Применить ко всем» = `Batch.choice` for the rest of that `UploadDialog` batch) and retried once with `on_conflict=replace`/`keep_both`; «Отмена» drops the item, abort answers it; `upload_in_progress` stays a toast; no client permission check for replace (403 surfaces). Waiting/warnings show via `waitingText`/`warningText` (`taskWaiting.*`/`taskWarning.*` keys, fallback to backend text).
- Never show storage/file uuids: use `lib/names.ts` (`humanPath`, `taskTitle`, `storageName`); "unavailable" only for `available === false` (`isUnavailable`).
- Search state lives in the URL of `/search` (`lib/search.ts`: `parseSearch`/`searchUrl` for the page, `searchQuery` for the API); the global bar is `components/search-bar.tsx` (outside the keyed `<main>` so it keeps focus across navigation). Never send an empty search (`hasCriteria`).
- Folder listing is paged and sorted by the backend (`GET /api/folders` with `sort_by`/`sort_order`/`folders_first`/`lang` = UI language, `limit` = `interface.page_size` 20|50|100|200, default 20, via `pageSizeOf`, part of `listingKey`, `cursor` = `next_cursor`): `useInfiniteQuery` over `listingKey`, pages merged by `listingEntries` (`lib/files.ts`), next page on an `IntersectionObserver` sentinel (`LoadMore`, 600 px ahead, «Показать ещё» button as fallback); folder links prefetch their first page on mouse hover / keyboard focus (`listingOf`, `PREFETCH_STALE_MS`, never on touch); no client re-sort. Header totals come from the first page only (`listingTotals`; cursor pages carry `null` totals); select-all/Ctrl+A/Shift-range act on loaded items, the toolbar shows «выбрано N из M» (M = `total_folders + direct_files`). Search order comes from the backend (`lang` = UI language in `searchQuery`, ICU collation across pages); no client re-sort.
- Optional extras (sounds, eggs+tips) are behind `lib/features.ts` (`interface.fx_*` settings), default off except eggs+tips (`fx_easter_eggs` true); the activity map is a dashboard block (hidden = not mounted, no `/files/activity` query) and skips animation under reduced motion. No new dependencies for effects. Pet, the upload speedometer, pixel cursor, confetti and achievements were removed: unknown `fx_*` keys from the server are ignored, `tcloud.achievements` is cleared with `LEGACY_KEYS`.
- Dashboard uses only existing endpoints; the System block is a rack (`HealthRack` in `components/health.tsx`, rows from `healthRows`; `HEALTH_GROUPS` is the single list of checks with RU/EN names and hints, reused on `/telegram`); admin-only queries (`users`) are `enabled`/rendered only for admins; the first-run checklist (`telegram` query) only for root. The «Превью» block hides for everyone when `GET /api/account` → `previews_enabled` is false; its «Очистить» (`DELETE /api/files/previews`) is root-only and the only place to clear previews; the global switch is root-only `uploads.previews` on `/settings`. Block order: `DASHBOARD_BLOCKS` ids in `lib/dashboard.ts` (must match the backend Literal), `blockOrder`/`moveBlock`; hidden blocks `interface.dashboard_hidden` (`hiddenBlocks` also migrates the old `activity_map: false` while the server omits the field, `visibleBlocks`), toggled by «Показывать» in edit mode where hidden blocks stay visible dimmed; edit mode («Настроить») is a local draft of order + hidden, saved on «Готово», dropped on «Отмена»/Esc; unsaved drafts are guarded by `useBlocker` + `Confirm` and `beforeunload`. The router is a data router (`createBrowserRouter`, one `*` route → `App` with `<Routes>`) so `useBlocker` works.
- Thumbnails: only via `Thumb` / `thumbUrl` (`lib/thumbs.ts`): `/api/files/{id}/thumb?v=<updated_at>`, for every kind but audio (documents and encrypted files too; a 404 is normal), lazy, a failed URL falls back to the kind icon and is not retried. Never load full images from `/download` in listings.
- Upload dialogs start from `settings.uploads` (`uploadOptions`) and still send every option explicitly; `withSendAs` turns encryption off for `media` and back on for `file`. Archive menus use `settings.archives` (format first, priority sent).
- Uploads keep relative paths (folder upload); the backend creates parent folders. Bulk download = one archive of the selection (`POST /api/folders/archive/selection`, `selectionPayload`/`archiveError` in `lib/archive.ts`), tracked like any archive task.

## Rules

- Plan first; important decisions go to the owner as multiple-choice questions.
- No code comments; explanations go to `docs/`. Keep README.md, `docs/` and this file current.
- README stays short: project overview, architecture diagram, main backend endpoints and pages, quick start, links to `docs/`. Implementation details go into `docs/` (UI behaviour → `docs/ui.md`).
- When code changes a flow shown in `docs/`, update the doc and its diagram in the same commit.
- Tests for new logic in `src/lib`. Commits: one-line English (`feat:`, `fix:`), **never push**.
